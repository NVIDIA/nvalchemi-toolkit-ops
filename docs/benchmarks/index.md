# Benchmarks

Performance benchmarks for ALCHEMI Toolkit-Ops GPU kernels, covering both
the **Torch** and **JAX** backends. These pages present scaling behaviour
across system sizes, constant-workload sweeps, and batch-scaling modes for
each module.


## Methodology

### Timing

| Backend | Mechanism | Details |
|---------|-----------|---------|
| **Torch** | CUDA Events | `start_event.record()` / `end_event.record()` around the kernel call, then `torch.cuda.synchronize()`. No host-side sync inside the timed loop. |
| **JAX** | Wall-clock + `block_until_ready` | `time.perf_counter()` before and after the kernel; `jax.block_until_ready(result)` after the **last** call in the batch to flush the dispatch queue. No per-iteration sync. |

For every configuration the benchmark runs *warmup* iterations (default 10)
followed by *timing* iterations (default 20, configurable via
``parameters.timing_runs`` in each module's YAML). The reported value is the
**mean time per call** across a single batch of N back-to-back runs, with
host/device synchronisation only at the start and end of the batch.

### Scaling modes

Each benchmark page presents three scaling modes:

System Size Scaling
: Fix batch size = 1, sweep the number of atoms per system.

Constant Workload
: Fix total atom count, sweep batch size (fewer atoms per system, more
  systems). Reveals per-launch overhead.

Batch Scaling
: Fix atoms per system, sweep batch size. Reveals how well the kernel
  amortises fixed overhead across systems.

### Systems

| System | Source | Description |
|--------|--------|-------------|
| **CsCl** | `pymatgen` `Structure` + `make_supercell` | BCC CsCl supercells (2 atoms/unit cell, cubic 4.14 A). |
| **NH₃** | PDB files generated by `benchmarks/nh3/generate_pbc_pdbs.sh` (requires [packmol](https://m3g.github.io/packmol/)) | Periodic ammonia boxes at powers-of-two atom counts. |

## Running the full suite

The three modules share a single entry point,
``benchmarks.benchmark_suite``, which loads each per-module
``benchmark_config.yaml`` and dispatches in-process. Run from the
repository root:

```bash
# All three modules, Torch backend (default)
python -m benchmarks.benchmark_suite --benchmark all \
    --output-dir docs/benchmarks/benchmark_results

# All three modules, JAX backend
XLA_PYTHON_CLIENT_PREALLOCATE=false \
python -m benchmarks.benchmark_suite --benchmark all --backend jax \
    --output-dir docs/benchmarks/benchmark_results

# Or a subset:
python -m benchmarks.benchmark_suite --benchmark nl d3 --backend torch
```

Because ``save_results`` appends when the CSV schema matches, running
the Torch suite and then the JAX suite against the same
``--output-dir`` produces unified CSVs with rows for both backends —
which is how the shipped plots are built.

### Wall-time on NVIDIA H100 80GB HBM3

Measured on a single H100 80 GB HBM3 with the shipped YAML
defaults (``timing_runs: 20``, ``warmup_runs: 10``, both systems,
all three scaling modes). Numbers are rounded indicatively; your
mileage will vary.

| Module | Torch | JAX |
|---|---|---|
| Neighbor List | ~3 min | ~15 min |
| DFT-D3 | ~4 min | ~15 min |
| Electrostatics | ~5 min | ~45 min |
| **Full suite, one backend** | **~10 min** | **~75 min** |
| Both backends, back-to-back | — | **~85 min** |

These numbers cover **only the benchmark runs themselves**. They
do not include one-time prep: environment install, JAX cold-cache
compile warmup, or NH₃ PDB generation via
``benchmarks/nh3/generate_pbc_pdbs.sh`` (requires packmol; run
once before the first benchmark).

```{note}
The JAX suite's ~75 min wall-clock is mostly XLA compile overhead,
not kernel speed — per-call times in the CSVs exclude compile, so
the plots are apples-to-apples. Set
``XLA_PYTHON_CLIENT_PREALLOCATE=false`` before JAX runs or XLA grabs
all VRAM. A persistent ``JAX_COMPILATION_CACHE_DIR`` skips
recompilation on repeat dev runs but is off by default (shipped
CSVs are cold-cache).
```

If you only need a smoke test, cap the runtime:

```bash
python -m benchmarks.benchmark_suite --benchmark all \
    --timing-runs 3 --warmup-runs 1 \
    --system cscl --mode system_size \
    --output-dir /tmp/smoke
```

This completes in under a minute on an H100 and exercises every
runner path end-to-end (used by `test/test_benchmarks_smoke.py` and
the developer-facing verification harness).
